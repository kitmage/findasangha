# Fluent Forms + FluentCRM on Find a Sangha

Settled 2026-10-26 (Mike's call): the site's forms run on Fluent Forms, people
and outreach live in FluentCRM, and the `fas-directory` plugin stays the
source of truth for listings, verification, and moderation.

## Division of labor

- **Fluent Forms (free core)** is the front door: form rendering, entries,
  honeypot and token spam layers, login-required restrictions.
- **`includes/fluent.php`** is the brain: on `fluentform/submission_inserted`
  it turns submissions into directory data (pending listings, claim queue
  entries, Subscriber accounts), with duplicate checks, a 5/hour rate limit
  per identity, and admin + submitter emails.
- **FluentCRM (free core)** receives a contact ONLY when the person checks the
  explicit opt-in box on a form. The contact joins the "Find a Sangha Updates"
  list with a source tag (Registered account / Listing submitter / Listing
  claimant), status `subscribed` (consent was explicit in the form).
- Fluent Forms Pro and FluentCRM Pro are NOT required for this flow. Pro
  becomes interesting later (builder-managed post feeds, CRM email sequences
  and conditionals for the 180-day reconfirmation cycle).

## The forms

Definitions are generated by `tools/gen_forms.py` into `data/forms/` and are
the source of truth. Create them on the server with:

```
wp eval-file deploy/create-fluent-forms.php     # creates, stores IDs in options
FAS_FF_UPDATE=1 wp eval-file deploy/create-fluent-forms.php   # refresh from repo
bash deploy/wire-fluent-pages.sh                # page content + shortcodes
wp fas fluent-status                            # show the configured form IDs
```

Form IDs are stored in options `fas_fluent_register_form_id`,
`fas_fluent_submit_form_id`, `fas_fluent_claim_form_id`.

| Form | Page | Who | Result |
| --- | --- | --- | --- |
| FaS Create Account | /create-account/ | anyone | Subscriber account + welcome email; auto sign-in |
| FaS Submit a Sangha | /add-your-sangha/ | signed-in users | `sangha_listing` with status **pending** |
| FaS Claim a Listing | /claim-your-listing/ | signed-in users | `fas_claim` with status **pending** |

## Field notes

- Listing submissions reuse the importer's duplicate rule (same title + city,
  or same website domain). A possible duplicate still lands as a pending
  listing, flagged with `_fas_potential_duplicate_of` for the moderator.
- Submitter identity is kept in `_fas_submitted_by` and the Fluent entry ID in
  `_fas_fluent_entry_id` on both listings and claims.
- Timezones are validated against PHP's identifier list; invalid values are
  dropped rather than stored.
- Taxonomy options on the form match the terms actually in use on the site
  (Insight, Zen, Plum Village, Retreats...). The seeded long-form variants
  ("Insight / Vipassana", "Zen / Chan / Seon / Thien", "Plum Village
  tradition", "Retreats offered") currently hold no published listings and
  are a known tidy-up item.
- The Fluent demo forms created on activation (Contact Form Demo,
  Subscription Form) are unused by the site and can be deleted in the admin.

## Spam posture

Login requirement on the submit and claim forms, Fluent's honeypot and token
protection, the handler's rate limit, and human moderation of every pending
item. No CAPTCHA keys are configured; add Cloudflare Turnstile in Fluent's
global settings if spam ever becomes real.
